### 1. SUMMARY AND OVERALL IMPACT STATEMENT

This manuscript introduces `Du Novo 2.0` (benchmarked using version 2.15), an updated reference-free consensus sequence caller for Duplex Sequencing (DS) libraries that adds three algorithmic improvements: (1) reference-free barcode error correction by indexing all concatenated $12 + 12$ bp ($ab$ and $ba$) duplex tags with `Bowtie` (FM-index), aligning all tags against the index within a user-defined edit distance ($d \in \{1, 2, 3\}$) and mapping quality ($\text{MAPQ} \ge 20$), building a `networkx` connected-component graph, and collapsing each component to the barcode tagging the largest number of reads; (2) replacing `MAFFT` with a C-level Python integration of `Kalign2` for within-family multiple sequence alignment; and (3) replacing synchronous batch multiprocessing (`W` jobs) with a buffered work queue (`M \times W` jobs, default $M = 8$). The authors evaluate `Du Novo 2.0` on two empirical datasets (`ABL1` imatinib-resistance amplicons and `pBR322` plasmid evolution) and an in silico duplex sequencing simulator (400,000 and 40,000 simulated duplex reads/fragments). Source code (`GitHub`), `Bioconda` packages, and `[WORKFLOW_PLATFORM]` (Galaxy) wrappers are openly available.

The core engineering ideas—using an FM-index (`Bowtie`) to avoid $O(N^2)$ pairwise edit-distance comparisons across >$10^6$ duplex barcodes, calling `Kalign2` directly in-memory from Python, and buffering worker queues—deliver a clear $7\text{--}9\times$ wall-clock speedup (Table 3) and recover $12\%\text{--}23\%$ more Duplex Consensus Sequences (DCSs) by rescuing singleton reads whose barcodes suffered a 1–3 bp PCR/sequencing error (Table 1). However, several numerical inconsistencies and methodological ambiguities in the manuscript's validation tables require correction: (1) in Table 2, the sensitivity/recall of barcode correction ($\text{TP}/(\text{TP}+\text{FN}) = 67.28\%$ at $d=1$ and $77.97\%$ at $d=3$) is mislabeled under the column header `Negative (%)` as "True Negative," and the total number of corrected families cited in the text ($816,335$ and $936,582$) exceeds the total number of simulated duplex reads ($400,000$); (2) in Table 4, the reported output DCS error rate on a homogenous simulated template is $0.00563\text{--}0.00525$ differences per base (written as $0.563\%\text{--}0.525\%$ in Table 4), which is **fivefold higher** than the raw input simulated sequencing error rate ($0.001$ per base, line 110) and orders of magnitude above the $<10^{-7}$ error rate characteristic of Duplex Sequencing, without explanation; and (3) collapsing entire connected components in `networkx` via single-linkage edges can chain barcodes across edit distances $>d$ or merge distinct families when tag diversity is lower (e.g., shorter UMIs or high input molecule counts). All of these issues can be addressed through table corrections, clarified simulation accounting, and post-trimming DCS error-rate reporting.

### 2. SPECIFIC CONCLUSIONS AND ASSESSMENT OF SUPPORT

* **Replacing `MAFFT` with in-memory `Kalign2` and buffered multiprocessing queues accelerates family alignment by $6\text{--}9\times$ across 1 to 32 CPU cores: [Well Supported].**  
  Figure 4 and Table 3 provide clean, controlled wall-clock and memory benchmarks across 1, 2, 4, 8, 16, and 32 CPUs, isolating both the aligner speedup (`2.15 MAFFT` vs. `2.15 Kalign2`: $28,754\text{ s} \to 4,731\text{ s}$ on 1 CPU) and the queue-buffering speedup at high core counts (`0.4 MAFFT` vs. `2.15 MAFFT`: $1,747\text{ s} \to 854\text{ s}$ on 32 CPUs).

* **`Bowtie` FM-index barcode error correction recovers singleton reads and increases DCS yield by $12\%\text{--}16\%$ in empirical datasets (`ABL1` and `pBR322`) and $22\%\text{--}23\%$ in simulations: [Well Supported].**  
  In Table 1, allowing edit distance $d = 1\text{--}3$ reduces single-strand consensus counts slightly (as false split families merge) while increasing paired Duplex Consensus Sequences from $20,745$ to $23,180$ ($+11.7\%$) in `ABL1`, from $77,164$ to $89,513$ ($+16.0\%$) in `pBR322`, and from $43,344$ to $53,454$ ($+23.3\%$) in the 400,000-read simulation.

* **In simulated data of 400,000 duplex reads, barcode correction at edit distance 1 makes only 5 false-positive corrections out of 816,335 corrected families ($99.999\%$ precision) and achieves $67.28\%$ true-negative rate (Table 2): [Methodologically Flawed].**  
  Table 2 and line 48 contain two internal inconsistencies:
  1. *Sample size vs. family count contradiction:* Line 48 states that *"The barcodes of 400,000 simulated duplex reads were corrected... Each family was counted once, rather than each raw read,"* yet reports *"816,335 corrections"* at $d = 1$ and *"936,582 corrected"* at $d = 3$. It is mathematically impossible for 400,000 reads to contain 936,582 distinct corrected barcode families unless the simulation actually comprised $\ge 400,000$ original DNA fragments (yielding millions of reads after 25 PCR cycles) or counted individual barcode strings/orientations rather than families.
  2. *Mislabeling Sensitivity/Recall as True Negative % in Table 2:* In line 48, the authors state that at $d = 1$, *"Du Novo was only able to catch and correct 67.28% of barcodes containing errors,"* leaving $32.72\%$ of error-containing barcodes uncorrected (false negatives). By standard confusion-matrix definitions, $\frac{\text{TP}}{\text{TP} + \text{FN}} = 67.281\%$ is the **True Positive Rate (Recall/Sensitivity)** and $\frac{\text{FN}}{\text{TP} + \text{FN}} = 32.721\%$ is the **False Negative Rate**. Yet in Table 2 (lines 53–59), `67.281%` and `32.721%` are placed in the `True` and `False` rows under the column header **`Negative (%)`**, whereas the `Positive (%)` column reports Precision ($\frac{\text{TP}}{\text{TP}+\text{FP}} = 99.999\%$) and False Discovery Rate ($\frac{\text{FP}}{\text{TP}+\text{FP}} = 0.001\%$).

* **`Du Novo 2.0` (`Kalign2` + barcode correction) achieves high consensus base accuracy on simulated homogenous sequences, with an error rate of $0.00525$ ($0.525\%$) differences per output base compared to $0.0114$ ($1.140\%$) for the standard Loeb pipeline (Table 4): [Fragile].**  
  The central premise of Duplex Sequencing (stated on line 12) is that requiring double-stranded consensus agreement reduces the per-base error rate from the standard sequencing error rate ($\sim 10^{-3}$) down to $10^{-5}\text{--}10^{-9}$. Yet in the simulation of 40,000 homogenous error-free fragments subjected to PCR and sequencing error rates of $0.001$ per base (line 110), Table 4 (lines 80–89) reports an output DCS error rate of `0.00563` to `0.00525` differences per base in the text—and prints those numbers as `0.563%` to `0.525%` in Table 4! First, `0.00563 differences per output base` is $0.563\%$, which is **five times worse** than a single raw un-duplexed sequencing read ($0.1\%$ error rate) and 4–5 orders of magnitude higher than expected for DCSs. If this high discrepancy rate is caused by counting untrimmed `N` ambiguity calls or ragged alignment ends as "errors" (or if `0.00563%` was intended, i.e., $5.63 \times 10^{-5}$), the authors must explain why the simulated DCS error rate exceeds the raw base error rate or correct the unit scaling between line 80 and Table 4.

### 3. CONSTRUCTIVE AND DOABLE SUGGESTIONS FOR IMPROVEMENT

#### 1. Reconcile the Simulated Read/Family Counts and Fix the Confusion Matrix Labels in Table 2
* **WHY:** Reporting 816,335 and 936,582 corrected families from "400,000 simulated duplex reads" (line 48) is numerically impossible if each family is counted once, and labeling Recall ($\text{TP}/(\text{TP}+\text{FN}) = 67.281\%$) as "True Negative (%)" in Table 2 confuses readers.
* **WHAT:** Clarify the exact denominator of the simulation in Table 2 (e.g., whether 400,000 initial molecules were simulated, producing several million PCR-amplified reads, or whether raw reads/tags were counted) and relabel the columns of Table 2 using standard statistical metrics.
* **HOW:** Replace the ambiguous `Positive (%)` and `Negative (%)` headers in Table 2 with explicit formulas: **Precision / PPV** ($\frac{\text{TP}}{\text{TP}+\text{FP}}$), **False Discovery Rate** ($\frac{\text{FP}}{\text{TP}+\text{FP}}$), **Sensitivity / Recall** ($\frac{\text{TP}}{\text{TP}+\text{FN}}$), and **False Negative Rate** ($\frac{\text{FN}}{\text{TP}+\text{FN}}$), alongside the exact integer counts ($\text{TP}, \text{FP}, \text{TN}, \text{FN}$), and fix the stray period typos (`99.710.` and `0.290.`) in rows 58–59.

#### 2. Resolve the Unit Discrepancy (`0.00525` vs. `0.525%`) and Explain the High DCS Error Rate in Table 4
* **WHY:** Line 80 states an error rate of `0.00525 differences per output base`, while Table 4 prints `0.525%`. Even if `0.00525%` ($5.25 \times 10^{-5}$) was meant, a genuine duplex consensus of $\ge 3$ forward and $\ge 3$ reverse reads with per-base error rate $p = 10^{-3}$ should have a substitution error rate on the order of $p^4 \sim 10^{-12}$ (or $\sim 10^{-6}$ if early-cycle PCR errors occur on one strand only, which are masked as `N` during SSCS-to-DCS pairing).
* **WHAT:** Clarify whether "differences per output base" in Table 4 includes ambiguous `N` bases generated when forward and reverse SSCSs disagree (which is the expected behavior of Duplex Sequencing when a 1st-cycle PCR error occurs on one strand) vs. actual false-positive non-`N` base substitutions (`A/C/G/T` mismatches).
* **HOW:** Separate Table 4's error metric into two columns: (1) **Ambiguous (`N`) base fraction** per DCS base, and (2) **False-positive substitution rate** (non-`N` mismatches against the true reference per called DCS base), and harmonize the decimal vs. percentage notation between line 80 and Table 4.

#### 3. Bound Single-Linkage Chaining in the `networkx` Barcode Graph (`correct.py`)
* **WHY:** In lines 36 and 108, `correct.py` builds an undirected graph where edges connect any two barcodes within edit distance $d$, and collapses each connected component to the most abundant vertex. Under single-linkage connected components, a chain of barcodes $B_1 - B_2 - B_3$ can merge $B_1$ and $B_3$ at distance $2d$, and if a singleton lies at distance $1$ from two abundant barcodes, `bowtie --best -a` will draw edges to both, merging two independent molecule families into a single chimeric family.
* **WHAT:** Restrict barcode absorption to star-like neighborhoods (depth 1 from a local maximum vertex) and discard ambiguous bridge barcodes that have equal edit distance to two distinct high-count parent families.
* **HOW:** In `correct.py`, sort vertices in descending order of read count, greedily assign neighbors within edit distance $\le d$ to the highest-count parent, and drop singleton bridge nodes that are equidistant from two already-instantiated parent hubs.
